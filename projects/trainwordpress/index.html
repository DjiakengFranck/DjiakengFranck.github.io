Project Overview

TrainWordPress is an educational website improvement project focused on creating a clearer and more accessible learning experience. The work includes website design improvements, WordPress theme configuration, content organisation and troubleshooting.

Agile Team Charter

This charter establishes the purpose, objectives, scope, responsibilities and working approach for the TrainWordPress website improvement project.

1. Project Information

  • Project: TrainWordPress Website Improvement
  • Organisation: AppManiazar
  • Project period: 7 October 2026 – 4 November 2026
  • Methodology: Scrum

2. Project Purpose

The purpose of this project is to improve the existing TrainWordPress educational website by creating a more accessible, organised and user-friendly learning experience. The project focuses on helping visitors discover tutorials, navigate learning resources and access WordPress educational content more effectively.

3. Project Objectives

  • Improve the overall visual presentation of the website.
  • Improve the organisation and discoverability of tutorials.
  • Enhance navigation between courses, topics and learning resources.
  • Improve website responsiveness across different screen sizes.
  • Configure and customise the Kadence WordPress theme.
  • Resolve identified website functionality and content issues.
  • Obtain stakeholder feedback and refine the implementation.

4. Project Scope

In Scope:

  • Redesigning the existing website presentation, including the homepage.
  • Migrating from the Zento Child theme to Kadence.
  • Improving tutorial categories and content navigation.
  • Reviewing learning-platform references such as Learn WordPress and WPBeginner.
  • Improving the website footer and contact form.
  • Restoring missing media and addressing identified website issues.
  • Testing responsive layouts and gathering feedback.
  • Adding an under-construction page during maintenance activities.

5. Working Approach

The project uses an iterative Agile Scrum-inspired approach. Work is organised into tasks, progress is monitored regularly, and completed improvements are reviewed before further refinements are made.

  • Daily progress: Regular updates on assigned work and current progress.
  • Weekly meetings: Discussion of project progress, requirements and challenges.
  • Reviews: Stakeholder feedback is considered when evaluating completed improvements.
  • Refinement: Identified issues and feedback inform subsequent changes.

6. Roles and Responsibilities

  • Developer / WIL Student: Research, website configuration, implementation, testing, documentation and progress reporting.
  • Supervisor / Stakeholder: Provide project direction, review progress and communicate feedback.
  • Project Team: Participate in discussions, reviews and feedback where required.

7. Communication and Collaboration

Communication takes place through regular project discussions, progress updates and team meetings. Feedback is used to clarify requirements, identify improvements and keep the project aligned with its objectives.

8. Quality Assurance

  • Check website functionality after implementing changes.
  • Test navigation links and learning-resource routes.
  • Verify contact form validation.
  • Review layouts on desktop, tablet and mobile.
  • Check media, content presentation and footer consistency.
  • Request stakeholder feedback where appropriate.

9. Expected Outcomes

The expected outcome is an improved TrainWordPress learning platform with clearer navigation, better-organised educational resources, a more consistent visual presentation and improved accessibility across devices.

PROJECT REQUIREMENTS / 02

User Stories & Tasks

Functional requirements expressed from the perspective of website visitors, learners and project stakeholders. Each user story includes acceptance criteria and associated implementation tasks.

US-01 DESIGN

Improved Website Design

As a visitor, I want a visually appealing and organised website so that I can navigate the learning platform comfortably.

01 Acceptance Criteria

  • The website uses a consistent visual design.
  • The Kadence theme is configured appropriately.
  • Page layouts are clear and readable.

02 Implementation Tasks

Review the existing theme, configure Kadence and refine website layouts.

US-02 CONTENT

Homepage and Tutorial Discovery

As a learner, I want to discover tutorials and learning categories easily so that I can find relevant WordPress resources.

01 Acceptance Criteria

  • The homepage presents learning resources clearly.
  • Tutorials and categories are organised logically.
  • Visitors can identify relevant learning content.

02 Implementation Tasks

Improve homepage sections, tutorial listings and category presentation.

US-03 NAVIGATION

Navigation and Footer

As a visitor, I want consistent navigation and useful footer links so that I can move around the website easily.

01 Acceptance Criteria

  • Navigation elements are consistent.
  • Important footer links are available.
  • Links direct visitors to the correct pages.

02 Implementation Tasks

Review the header, organise footer content and test navigation links.

US-04 FUNCTIONALITY

Contact Form

As a visitor, I want the contact form to work correctly so that I can submit enquiries.

01 Acceptance Criteria

  • Required fields are validated.
  • Invalid submissions are handled appropriately.
  • The form provides a usable submission experience.

02 Implementation Tasks

Inspect the contact form, correct identified issues and test validation.

US-05 MEDIA

Website Media

As a learner, I want tutorial images and media to display correctly so that I can understand the learning content.

01 Acceptance Criteria

  • Required images are available.
  • Media displays correctly on relevant pages.

02 Implementation Tasks

Investigate missing media, check backup files and restore required images.

US-06 RESEARCH

Learning Platform Research

As a project stakeholder, I want the website design to consider established WordPress learning resources so that useful practices can inform improvements.

01 Acceptance Criteria

  • Relevant learning platforms are reviewed.
  • Useful design and content organisation practices are identified.

02 Implementation Tasks

Research IsItWP, Learn WordPress and WPBeginner and document relevant observations.

US-07 RESPONSIVENESS

Responsive Experience

As a visitor using different devices, I want the website to adjust to my screen size so that I can access learning resources comfortably.

01 Acceptance Criteria

  • Layouts are reviewed on desktop, tablet and mobile.
  • Content remains readable and accessible.
  • Navigation and page elements remain usable.

02 Implementation Tasks

Review responsive settings and test page layouts across device sizes.

US-08 FEEDBACK

Stakeholder Feedback

As a stakeholder, I want to review website improvements and provide feedback so that the final experience meets project expectations.

01 Acceptance Criteria

  • Website improvements can be reviewed.
  • Feedback is considered during refinement.
  • Relevant changes are implemented where appropriate.

02 Implementation Tasks

Share website updates, collect feedback and refine identified areas.

US-09 MAINTENANCE

Maintenance Communication

As a visitor, I want to see a maintenance or under-construction notice when the website is being updated so that I understand why normal access may be affected.

01 Acceptance Criteria

  • A maintenance page is available.
  • The notice communicates the website's maintenance status clearly.

02 Implementation Tasks

Install and configure the under-construction page and verify its display.

23 OCTOBER 2026 WORDPRESS MIGRATION

Kadence Migration and Media Restoration

Worked on the migration from the Zento Child theme to Kadence, resolving import, media and hosting storage challenges.

Development Activities

  • Continued migration from the Zento Child theme to Kadence.
  • Attempted a full website import, which stalled at 22.85%.
  • Prepared and imported a smaller 106,786 KB export, which completed successfully without the media files.
  • Investigated missing images by checking the live WordPress uploads directory.
  • Found that the October 2026 uploads folder on the live site was empty while the matching LocalWP folder contained the required pictures.
  • Restored the required media files from the LocalWP installation.
  • Activated Kadence on the live website and checked the restored media.
  • Deleted an older 498.86 MB backup to remain within the 2,000 MB hosting quota.
  • Collected colleague feedback and continued researching other WordPress learning platforms.
  • Refined the unpublished homepage design, including the hero section, categories and content hierarchy.
TECHNICAL CHALLENGES
  • The full migration process stalled during import.
  • Hosting storage limitations required backup management.
  • Media files were not included in the successful smaller import and needed to be restored separately.
OUTCOME

The smaller import completed, Kadence was activated and the required media was restored. Homepage refinements continued without replacing the live homepage.

DEVELOPER REFLECTION

Website migration requires careful backup management, storage monitoring and verification of media files. Troubleshooting also highlighted the importance of maintaining a working local copy.
